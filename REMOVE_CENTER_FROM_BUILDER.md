Remove center from all methods of TemplateConfigHandle (add_rotated, add_scaled, add_*_range)... Instead, the Matcher decides which center should be used. It's often confusing for Users, because it has to be a pixel center and most of the times, the center is between two pixels (for even ROI width/height). It's also not obvious why the center doesn't need to bee the position the user is interested in... Defining e.g. a pickpoint could even be outside of the matching-Template in theory... This point should be choosen for minimal Template-Size, when we rotate all features around it (so the point, with Min(Distance of all features)). And is not necessarily the center, if e.g. all features are found on the left side of the template.

I'd even add a new option for Detector to define the pickpoint. If nothing is defined, it should return (x,y,angle=0) of the Template ROI (topleft). Since this point is only needed before returning the matches, it could be a setter on the Detector directly (not settable via DetectorBuilder), since it doesn't affect anything else in the Detector.
